## Subsystem Catalog

### 1. Knowledge Graph

**Owner:** Platform Engineering  
**Version:** 1.0.0 (Frozen)  
**Entry Point:** [`docs/ARCHITECTURE/GRAPH_SPECIFICATION.md`](GRAPH_SPECIFICATION.md)

**Purpose:**  
Single source of truth for all entity data (agents, categories, comparisons, research) and their relationships. Provides graph traversal and query capabilities.

**Key Contracts:**
- `GraphNode` — Node with id, type, data
- `GraphEdge` — Edge with from, to, type, properties
- `GraphData` — Complete graph with nodes, edges, metadata

**Public API:**
- `GET /api/graph/stats` → Graph statistics
- `GET /api/graph/related/:entityType/:entityId` → Connected entities
- `GET /api/graph/similar/:entityType/:entityId` → Similar entities
- `GET /api/graph/path/:fromType/:fromId/:toType/:toId` → Shortest path

**Invariants:** 8 rules covering edge validity, unique IDs, deterministic resolution  
**Build Artifact:** `graph-data.json` (auto-generated by `scripts/build-graph.ts`)  
**Verification:** `npm run test:graph` (verify-graph.ts)

**Dependencies:** None (source of truth)  
**Dependents:** Content OS (Entity Resolver), RelatedAgents widget, Blueprint Engine

### 2. Content OS

**Owner:** Content Platform  
**Version:** 1.0.0-draft (Frozen pending sign-off)  
**Entry Point:** [`docs/ARCHITECTURE/CONTENT_OS.md`](CONTENT_OS.md)

**Purpose:**  
Deterministic system that transforms canonical entities into validated, reproducible content through stable contracts.

**Key Contracts:**
- `ContentManifest` — Single source of truth for every page
- `EntityResolver` — Maps manifest references to canonical entities
- `GenerationContext` — Immutable context for blueprint generation
- `Blueprint` — Page-type-specific rendering logic
- `ValidationPipeline` — Quality and correctness rules
- `Evidence` — Source tracking and citations
- `QualityScorer` — Weighted scoring model
- `Linker` — Graph-derived internal link injection

**Public API:** (internal until v1.0.0 freeze)
- Manifest registry (Read-only)
- Resolver service
- Blueprint registry
- Validation CLI

**Invariants:** 8 system invariants (determinism, immutability, single source of truth, etc.)  
**Verification Suite:** Planned (per C1–C9 roadmap)

**Dependencies:** Knowledge Graph (entity resolution)  
**Dependents:** Editorial OS (content editing), Blueprint Engine (implementation)

### 3. API Contracts

**Owner:** Platform Engineering  
**Version:** 1.0.0 (Frozen)  
**Entry Point:** [`docs/ARCHITECTURE/API_CONTRACTS.md`](API_CONTRACTS.md)

**Purpose:**  
Define all external HTTP endpoints, request/response schemas, error codes, and rate limits.

**Key Endpoints:**
- Graph API (`/api/graph/*`)
- Recommendation API (`/api/recommend`)
- Lead capture (`/api/submit-lead`)
- Tool submission (`/api/submit-tool`)
- Subscribe (`/api/subscribe`)

**Schema Format:** JSON Schema draft-07  
**Auth:** None (public endpoints)  
**Rate Limiting:** None currently

**Verification:** Manual curl checks; production verification script (`scripts/verify-production.mjs`)

**Dependencies:** Server (Express)  
**Dependents:** Frontend clients, external consumers

---

### 6. Versioning Policy

**Owner:** Platform Engineering  
**Version:** 1.0.0 (Frozen)  
**Entry Point:** [`docs/ARCHITECTURE/VERSIONING.md`](VERSIONING.md)

**Purpose:**  
Define semantic versioning rules for contracts, deprecation policy, and backward compatibility guarantees.

**Key Policies:**
- Contracts: Semantic Versioning (MAJOR.MINOR.PATCH)
- v1.0.0 frozen → breaking changes require new MAJOR + ADR
- Backward compatibility guaranteed within same MAJOR
- Deprecations remain functional for one MAJOR cycle

**Applies to:** All public interfaces (Graph API, Content OS contracts, Blueprint API, Validation API)

## Contract Modification Process

1. **Draft**: Proposed change documented in ADR
2. **Review**: Stakeholder review and approval
3. **Freeze**: Version 1.0.0 declared stable
4. **Change**: Breaking changes require new MAJOR version
5. **Deprecate**: Old version supported for one MAJOR cycle, then removed

All contract changes **must** include:
- Updated interface definitions
- Migration guide (if breaking)
- Updated verification tests
-ADR record
