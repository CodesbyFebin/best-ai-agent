# CI Invariants — Production Deployment Gates

Six mandatory invariants that must pass for any production deployment. Each invariant maps to a specific enforcement mechanism in the codebase.

## Invariant 1: `approved evidence → required for published claims`

**Statement:** No published route may contain claims that lack approved evidence support.

**Enforcement:** 
- Opportunity Engine `evaluate()` has **Hard Gate 1: Evidence eligibility**
- If the candidate's subject entity has no approved evidence, or the candidate references unapproved evidence items, the engine forces `decision = QUARANTINE` with `opportunityScore = 0`
- The content generator may only render claims that have `evidence_status = 'approved'` in the persistence schema
- CI check: `hardGateFailures === 0` for any candidate that reaches `readyForManifestGeneration = true`

**Violation detection:** Any route rendered with `status: 'published'` that has `evidence_ids` not all approved → CI failure.

---

## Invariant 2: `failed hard gate → never publish`

**Statement:** If any of the 4 hard gates fails, the decision is forced to QUARANTINE regardless of opportunity score.

**Enforcement:**
- Engine evaluates hard gates in deterministic order: evidence eligibility → entity validity → cannibalization → freshness
- **Critical invariant:** "A high opportunity score can NEVER override a failed hard gate"
- If any hard gate fails, `evaluate()` returns `score = 0`, `decision = QUARANTINE`, `hardGateFailures >= 1`, `readyForManifestGeneration = false`
- The engine's `_forceQuarantine()` method explicitly sets score to 0, documented in the code comment

**Violation detection:** Opportunity score > 0 when `hardGateFailures > 0` → CI failure.

---

## Invariant 3: `canonical → exactly one production URL`

**Statement:** Every valid route path has exactly one canonical URL with `status: 'published'` and `indexable: true` in the route registry.

**Enforcement:**
- `src/routing/routeRegistry.ts` is the single source of truth for canonical routes
- `src/routing/routeResolver.ts` validates dynamic slugs against real entity registries; unknown slugs return `not-found` (→ HTTP 404) instead of being synthesized as `published` + `indexable`
- Each path in `canonicalRoutes` has a unique `path` key; duplicate paths are prevented by TypeScript type system
- Route records have `canonicalPath` field; the resolver ensures only one route per canonical path

**Violation detection:** Multiple route records with same `path` value, or dynamic routes synthesized without entity validation → CI failure.

---

## Invariant 4: `sitemap → canonical URLs only`

**Statement:** The sitemap generator emits only routes with `status: 'published'` AND `indexable: true`.

**Enforcement:**
- `scripts/sitemapGenerator.ts` filters `canonicalRoutes` by: `route.status === 'published' && route.indexable`
- The engine's `DecisionReport.readyForManifestGeneration` is `true` ONLY when `publishCount > 0 AND regressionTestsPassed`
- Content generators consult the DecisionReport before emitting sitemap entries
- Any route with `status !== 'published'` OR `indexable !== true` is excluded from sitemap

**Violation detection:** Sitemap contains URL for route with `status !== 'published'` OR `indexable !== true` → CI failure.

---

## Invariant 5: `manifest → approved DecisionReport only`

**Statement:** Content/schema/internal-link generators must only consume manifests generated by the Opportunity Engine's `evaluate()` method.

**Enforcement:**
- The Engine produces a `DecisionReport` with `reportId`, `generatedAt`, `engineVersion`, and decision distribution snapshots
- Manifest generators read the DecisionReport (via `reportId` or `engineVersion`) before generating any content
- The DecisionReport contains `readyForManifestGeneration: true` flag; generators must check this flag first
- Generators must not produce content for candidates that were quarantined, rejected, or redirected
- The `decision_report_decisions` table in the persistence schema stores per-candidate decisions for audit

**Violation detection:** Generator produces content for a candidate without checking `DecisionReport.readyForManifestGeneration` → CI failure.

---

## Invariant 6: `generator → cannot invent unresolved values`

**Statement:** No generator may invent or manually assert values that are not trace to approved evidence in the persistence schema.

**Enforcement (CORE ENGINE INVARIANT):**
- "A high opportunity score can NEVER override a failed hard gate" — this is the top-level invariant
- Specific manifestations:
  - **Price claims** must reference `evidence_records.confidence` and `evidence_records.currency` from approved evidence
  - **Rating claims** must reference `evidence_claims.confidence` from evidence store, not hard-coded "4.5"
  - **Feature lists** must be extracted from `evidence_records.passage`, not synthesized
  - **Time-sensitive values** (software versions, subscription prices) must have `valid_from`/`valid_until` metadata, not hard-coded
  - The `llms.txt`/`llms-full.txt` were revised to remove authority claims ("India's Premier", "Definitive", "verified", "independent", "empirical", "audit", "DPDP verified") that could not be traced to evidence

**Violation detection:** Any generated content contains manually asserted counts/claims without evidence traceability → CI failure. Specifically:
- "30+ server categories" without evidence record → fail
- "100+ integrations" without evidence → fail
- "ratingValue: 4.5" without evidence claim → fail
- "significantBloodPressure: false" without evidence → fail

---

## Invariant Verification Checklist

| Invariant | Enforcement Location | CI Check |
|-----------|---------------------|----------|
| 1. approved evidence → published claims | Engine hard gate 1 + generator code | `hardGateFailures === 0` for manifest-ready candidates |
| 2. failed hard gate → never publish | Engine `_forceQuarantine()` | score=0 whenever `hardGateFailures > 0` |
| 3. canonical → one production URL | routeRegistry + routeResolver | No duplicate `path` entries; dynamic slugs validated |
| 4. sitemap → canonical URLs only | sitemapGenerator.ts | Filter: `status === 'published' && indexable === true` |
| 5. manifest → approved DecisionReport | Generator code + DecisionReport | Check `readyForManifestGeneration` flag |
| 6. generator → no invented values | llms.txt/llms-full.txt revision + evidence schema | All claims trace to `evidence_records`/`evidence_claims` |

## Production Deployment Gate

A production deployment is authorized only when ALL 6 invariants pass. The deployment pipeline should:

1. Run Opportunity Engine evaluation on all new candidates
2. Verify `hardGateFailures === 0` for any candidate with `readyForManifestGeneration = true`
3. Verify route registry has no duplicate paths
4. Verify sitemap generator output filters correctly
5. Verify all generated claims have evidence traceability
6. Generate and regression-test the `chatgpt → coding-agents` fixture (both passing and hard-blocked variants)

**Failure on any invariant blocks deployment.**
