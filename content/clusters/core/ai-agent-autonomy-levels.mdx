# AI Agent Autonomy Levels

## Direct answer (AEO)

Autonomy describes how much of the perception-reasoning-action loop the agent controls without human approval. We use a four-level scale: L1 Assisted (agent suggests, human acts), L2 Supervised (agent acts within an approved scope, human audits), L3 Delegated (agent acts across an open scope, human reviews outputs), L4 Autonomous (agent acts end-to-end without human approval). The level is a deployment choice, not a property of the model.

## Key takeaways

- Autonomy is a **deployment choice**, not a model property.
- The four levels give a shared vocabulary for procurement, risk review, and incident response.
- HITL is mandatory at L2 and L3; L4 requires exceptional controls and is out of scope for most enterprise deployments today.
- **Autonomy downgrades** are a valid response to a model regression or a vendor incident.

## The four levels

### L1 — Assisted

The agent suggests an action; a human executes it. Examples: code completion with confirm-to-apply, an LLM that proposes a customer-support reply that a human sends.

- HITL: implicit (the human is in the loop by definition).
- Audit: the agent's suggestions are logged.
- Risk: low.
- Typical deployment: any.

### L2 — Supervised

The agent executes an action within an approved scope; a human audits the actions after the fact. Examples: a customer-support agent that replies within a known FAQ; a coding agent that opens a PR that a human reviews.

- HITL: post-hoc audit; some pre-execution review for high-cost actions.
- Audit: every action is logged with a correlation id.
- Risk: medium.
- Typical deployment: most production enterprise agents.

### L3 — Delegated

The agent executes across an open scope; a human reviews the outputs. Examples: a research agent that produces a report a human reviews; an analytics agent that writes SQL and queries a warehouse.

- HITL: output review; pre-execution review for consequential actions.
- Audit: every action is logged; outputs are versioned.
- Risk: medium-high.
- Typical deployment: advanced enterprise; smaller teams with strong review capacity.

### L4 — Autonomous

The agent executes end-to-end without human approval. Examples: autonomous trading bots; self-driving cars; large-scale code migration agents.

- HITL: exceptional controls only (kill switch, sandbox, rollback).
- Audit: comprehensive; usually requires a separate audit system.
- Risk: high; out of scope for most enterprise deployments today.
- Typical deployment: tightly scoped, high-confidence domains with strong rollback.

## HITL placement by level

| Level | Pre-execution HITL | Post-execution audit |
|-------|--------------------|----------------------|
| L1 Assisted | Implicit | Optional |
| L2 Supervised | For high-cost actions | Required |
| L3 Delegated | For consequential actions | Required for outputs |
| L4 Autonomous | Exceptional | Required; separate audit system |

## Autonomy downgrades

An autonomy downgrade is a deliberate move to a lower level in response to:

- A model regression (the model's quality drops).
- A vendor incident (the vendor has a security or reliability incident).
- A compliance finding (an auditor flags a risk).
- A user complaint pattern (users are consistently unhappy with the agent's outputs).

The downgrade is a workflow change, not a model change. The same model can run at L2 today and L3 next quarter. See [](/human-in-the-loop-agents).

## India-region considerations

- **DPDP.** L2 and L3 deployments that process Indian user data require a documented lawful basis, data principal rights processes, and breach notification. See [](/trust/privacy-dpdp-editorial-policy).
- **Sectoral regulators.** Healthcare, finance, and legal deployments may have sectoral autonomy limits regardless of the technical capability.
- **GST.** Higher autonomy often correlates with higher token / tool-call consumption; the cost impact on an Indian entity includes 18% GST.

## What we will not tell you

- We will not tell you which level is "the best." The right level depends on the use case, the team's review capacity, and the regulatory context.
- We will not score agents by autonomy level. A higher level is not a better agent.

## Frequently asked questions

### Is L4 (autonomous) the same as AGI?

No. L4 means an agent operates end-to-end in a tightly scoped domain without human approval. AGI is a hypothetical system that operates across every domain. The technical gap between L4 and AGI is enormous.

### Can an L2 agent be promoted to L3?

Yes. Autonomy changes are deployment decisions, not model changes. You can raise or lower the level without retraining the model.

### How do I know which level a deployment is at?

Inspect the workflow. Count the HITL checkpoints. If every consequential action has a pre-execution review, the deployment is L2. If the only review is post-execution audit, the deployment is L3.

### What level should my first deployment be?

L1 or L2. Start supervised; expand autonomy only after the audit log shows consistent quality. See [](/human-in-the-loop-agents).

### Is higher autonomy always better?

No. Higher autonomy means higher risk. The right level is the one that matches the team's review capacity and the regulatory context.
