# Corrections and Version History

Mistakes happen. The integrity of this site depends on how we record and correct them. This page documents the correction log format, severity classes, and the difference between a correction, a refresh, and a retraction.

## What a correction is

A correction is a published change to a claim that was incorrect when published. Corrections are surfaced on the affected page with a visible "Correction" note that links to the entry in this log.

A correction is not the same as:

- **Refresh** — re-verifying claims whose evidence aged past `expiresAt`. The claim may still be correct; we are checking.
- **Update** — expanding the page with new evidence or context.
- **Retraction** — withdrawing a page entirely because its central claim cannot be supported.

## Severity classes

We use three severity classes for corrections:

| Class | When | Page treatment |
|-------|------|----------------|
| **Minor** | Typographical error, broken link, formatting issue | In-page note, log entry |
| **Material** | A claim was wrong or out of date but the page's overall conclusion holds | In-page banner, log entry, optional `lastReviewed` reset |
| **Substantive** | The page's conclusion no longer holds, or the page is unsafe to use | Page moves to `refresh_required` or `rejected`, retraction notice on the index |

## Correction log format

Each entry in this log includes:

- Affected page slug
- Date of correction
- Severity class
- Brief description of the change
- Receipt that prompted the correction
- Reviewer name

## How to report a suspected error

Send corrections, supporting evidence, and the URL of the affected page to the address listed on [](/about). We aim to triage submissions within 7 calendar days and to publish either a correction entry or a written explanation of why we declined to correct.
